# Configuration

`factory_config.py` is the source of truth for repositories, labels, permissions, limits, sandbox timeout, install
commands, verification commands, repository egress, and whether traces carry content. Importing it validates the
configuration.

## Render environment groups

`render.yaml` creates and links group shells. Add values in the Render Dashboard; never commit them.

### `factory-gateway`

- `RENDER_API_KEY`: scoped to starting Workflow tasks when scoped keys are available.
- `GITHUB_WEBHOOK_SECRET`: generated by the GitHub App manifest flow.
- `LOGFIRE_TOKEN`: optional Logfire write token. See [Observability](#observability-logfire).
- `RENDER_WORKFLOW_SLUG`: defaults in the Blueprint to `factory-workflows`.
- `DATABASE_URL`: set on the service by the Blueprint from `factory-db`, not through the group.
- `PORT`: supplied by Render. The gateway binds `0.0.0.0:$PORT`.

The gateway intentionally has no GitHub App private key and no model key.

### `factory-workflows`

- `RENDER_API_KEY`: task-run and sandbox access.
- `RENDER_WORKSPACE_ID`: workspace that owns the sandbox group.
- `GITHUB_APP_ID` and `GITHUB_APP_PRIVATE_KEY`: App installation authentication.
- `ANTHROPIC_API_KEY`: used by the agent loops, which run in the Workflow task. It never enters a sandbox.
- `FACTORY_SANDBOX_GROUP_ID`: group for all factory sandboxes and snapshots.
- `LOGFIRE_TOKEN`: optional Logfire write token, separate from the gateway's.
- `LOGFIRE_PROJECT_URL`: optional; adds a Logfire trace link to status comments. See
  [Observability](#observability-logfire).
- `DATABASE_URL`: written by `setup-render --link-database --apply`. See [Database](#database).
- `GITHUB_API_URL`: optional GitHub Enterprise Server API base.

The Blueprint also sets `RENDER_WORKFLOW_SLUG=factory-workflows` on the Workflow service, so a Workflow task can
start another task as an independent root run.

`RENDER_ADMIN_API_KEY` is setup-only. It can be read by `setup-render`, but must never be added to either service.

The built-in agents pin `claude-sonnet-5-5` for Triage and PR Reviewer, and
`claude-opus-5-5` for Spec Writer and Implementer. Model IDs are explicit
rather than provider aliases so they remain compatible with the pinned
Pydantic AI model contract.

## Database

`factory-db` is a Render Postgres 17 database declared in `render.yaml` (`basic-256mb`, in `oregon` with the
services). It holds the append-only event log (`events`), the tables derived from it (`runs`, `threads`), and the
spend counters. Both services apply pending migrations themselves: Workflows on its first task, the gateway at
startup.

**Two URLs.** Render services in the same region use the internal URL, which is what the Blueprint provides. The
Blueprint sets `ipAllowList: []`, which blocks every connection from outside the workspace. To run `doctor`,
`preflight` or `db-rebuild` from a laptop, add your IP to `factory-db` in the Dashboard temporarily, and use the
external URL with certificate verification:

```text
postgresql://USER:PASSWORD@EXTERNAL-HOST/DATABASE?sslmode=verify-full&sslrootcert=system
```

The factory connects with asyncpg, and turns `sslrootcert=system` into a TLS context that verifies the server's
certificate and hostname against the system trust store. Remove your IP afterwards.

**The link step.** A Blueprint can give `DATABASE_URL` to the gateway but not to a Workflow service: every sync fails
with `depends on non-existent DB`. After the Blueprint has been applied, copy the gateway's value into the
`factory-workflows` group:

```bash
RENDER_API_KEY=... RENDER_WORKSPACE_ID=... uv run setup-render --link-database          # dry run
RENDER_API_KEY=... RENDER_WORKSPACE_ID=... uv run setup-render --link-database --apply  # writes
```

It finds the single `factory-gateway` web service (Render may add a suffix), reads its `DATABASE_URL`, and upserts it
into the group. It never prints the value. Redeploy `factory-workflows` afterwards so the running service sees it.
Rerun it whenever the database is rotated or recreated. `doctor --remote` checks that the group holds the key.

**Checks.** When `DATABASE_URL` is set, `preflight` and `doctor` connect with `select 1` and list pending migrations.
Pending migrations are a warning, because the services apply them when they start. When it isn't set, the check is
skipped. Neither command prints the URL or any part of its credentials.

**`db-rebuild`.** `uv run db-rebuild` replays the event log into the derived tables. Run it after a change to
projection code that alters derived rows. It needs `DATABASE_URL` and, from a laptop, the temporary external access
above.

**Connection budget.** The gateway's pool holds up to 10 connections, and each concurrent Workflows task process up
to 3. Keep the total within the plan's connection limit; move to a larger plan, or lower the Workflows pool, before
raising Workflows concurrency.

## Spend budgets

Pydantic AI Harness's `SpendLimits` prices every model response and refuses the next request once a budget is spent.
Budgets are set in `factory_config.py`; leave one unset to disable it:

```python
CONFIG = FactoryConfig(
    ...,
    spend=SpendSettings(agent_run_usd=Decimal(20), repo_day_usd=Decimal(100), day_usd=Decimal(250)),
)
```

- `agent_run_usd`: one agent run, such as one Implementer attempt or one repair round.
- `repo_day_usd`: every agent working on one repository, per UTC day.
- `day_usd`: the whole deployment, per UTC day.

Counters live in `factory-db` (`spend_counters` and `spend_dedup`, which the store creates on first use), on the
same asyncpg pool as the event log, so every Workflow instance enforces one budget. A run stopped by a budget fails
with "the … agent reached its spend limit." The request that crosses a ceiling completes, and concurrent runs can
each pass the check before either records its spend, so a budget can be exceeded by about one request per
concurrent run. Keep a spend limit at the model provider too.

## Observability (Logfire)

Tracing is optional. With `LOGFIRE_TOKEN` set in a service's environment group, that service sends traces to the
Logfire project the token belongs to (its region comes from the token); without it, nothing is sent. Use a separate
write token for each service so either can be revoked alone. `LOGFIRE_ENVIRONMENT` (for example `demo`) is read by
Logfire if set. Services are named `factory-gateway` and `factory-workflows`, and spans link to source lines on
GitHub through Render's `RENDER_GIT_REPO_SLUG` and `RENDER_GIT_COMMIT`.

What leaves the workspace is set in `factory_config.py`:

```python
CONFIG = FactoryConfig(
    ...,
    telemetry=TelemetrySettings(include_content=False),
)
```

- **`False` (default).** Traces carry timing, models, token counts, cost, tool names, progress, and outcomes, but no
  prompts, model output, tool arguments, or tool results.
- **`True`.** Traces also carry prompts, model output, and tool calls with their results. Those hold issue text and
  repository contents, which then leave your Render workspace. Logfire's scrubber checks field names, not the text of
  model messages, so a secret committed to a repository can reach Logfire. Turn it on deliberately, for example on a
  demo deployment.

Either way, HTTP headers and bodies are never captured, and strings shaped like GitHub, Anthropic, Render, or Logfire
credentials or PEM private keys are masked before export.

Every run span carries `factory.trace_id` and `factory.run_id` (the Render root task run and this task run), and
`factory.repo` and `factory.thread`. Find a Dashboard task run's trace in Logfire with
`attributes->>'factory.run_id' = '<trn-…>'`.

Set `LOGFIRE_PROJECT_URL` on `factory-workflows` to the project's URL, such as
`https://logfire-us.pydantic.dev/acme/factory`, and the GitHub status comment links **Trace in Logfire** for the run
it shows, while the run is still going. Without it, the comment has no link. Queries to `factory-db` appear as spans
with their SQL, never their parameters, which hold event payloads.

## Local files

`.env.example` documents every key. A populated `.env` is ignored by git. `preflight --env-file PATH` and
`doctor --env-file PATH` read it without printing values.
